# v2.2.0：1000 道菜谱与独立实拍照片

本版在 888 道菜库中合并同一道菜的“酸菜白肉汤”和“酸菜炖白肉”，保留“酸菜炖白肉”，再增加 113 道菜谱，合计 **1000 道**。新增内容分为热菜等 57 道与主食、小吃等 56 道；保留条目承接旧收藏记录，避免升级后收藏丢失。

生产站点继续使用同一个 [GitHub Pages 入口](https://jokerlixing.github.io/daily-dish/)。[888 道版本记录](catalog-888-status.md) 和 [旧分类统计](catalog-888-counts.json) 保留为历史，不代表本版数量或验收结果。

## 使用变化

- 随机主页删除菜名和食材搜索框及其筛选逻辑，保留菜系、不吃辣、素菜、时长与一次随机 1～10 道。
- “逛菜谱”保留菜名、食材和菜系搜索，以及八类菜式、每页 24 道、页码跳转和返回位置记忆。
- 冰箱保持独立入口，按已有食材列出“主料已齐”或仍缺的食材，不受随机主页筛选条件影响。
- “我的收藏”新增“清空收藏”，“最近抽到”新增“清空记录”；各自仅清空对应列表，并保存到当前浏览器。
- 继续支持手机、平板和电脑，以及离线打开、做法勾选和打印。

## 照片与去重

1000 道菜已接入各自独立的本地 WebP 实拍照片。旧版共享图片中的 55 处已替换；合并的酸菜白肉条目不再占用第二张图片。新增菜图与旧图库分别比对，不能通过更换文件名、复制、裁切或调色同一照片满足去重要求。

照片仍以同名成品为优先。主料与成品形态一致、仅配菜或摆盘有差异时，显示来源菜名及具体差异；照片下方保留作者、来源和权利说明。未声明开放许可的来源不标为 CC 或 MIT，具体见 [照片授权记录](photo-authorization.md) 和 `data/photos.json`。

视觉复核记录必须同时匹配菜品 id、图片路径和当前 WebP 文件的 SHA256。替换图片后，旧文件的通过记录不能作为新图的验收依据。全库同时检查本地文件路径、图片内容和去除查询参数后的原图地址；感知哈希仅提出候选，还需实际看图判断是否为同一照片。

## 发布验证

**本地验收通过：1000 道菜谱、1000 张独立图片，34 项自动测试、16 组浏览器功能检查、12 种屏幕宽度检查和 42 页全量浏览检查通过。** 新增清空功能已验证独立清空、刷新保存、跨标签同步和保留冰箱内容。逐图结果见 [逐菜照片复核报告](photo-review-report.json) 和 [相似照片复核记录](photo-similarity-review.json) 为准，核对报告数量为 1000 且状态为通过。

完整本地验收摘要见 [功能与布局报告](catalog-1000-verification.json)，图片去重结果见 [全库图片哈希报告](photo-uniqueness-report.json)。

常规构建与验证命令：

```sh
npm run build
npm test
node scripts/photo-release-check.mjs
```

图片审查还包括 `scripts/audit-photo-uniqueness.py` 的完整解码与哈希扫描、相似候选的逐对人工复核，以及 `artifacts/1000/finalize-review.cjs` 对当前文件视觉记录的汇总。该汇总依赖采集与审核工作目录中的记录，不是普通用户打开网页的前置步骤。

浏览器回归覆盖随机推荐、收藏和最近记录的分别清空、独立冰箱、逛菜谱搜索、分页与响应式布局。相关脚本为 `scripts/browser-check.cjs`、`scripts/catalog-browser-check.cjs`、`scripts/layout-check.cjs`；支持的环境参数见脚本与项目 README。页面继续通过同一个 GitHub Pages 地址发布，不增加第二个生产入口。
