# Daily Dish v2 验证记录

## 本轮变化

- 随机 1、2、3、4、5、6、7、8、10 道菜，桌内去重、候选不足显示实际数量、切换菜谱查看做法及整桌收藏。
- 全菜系模式覆盖 123 道非小吃菜谱；排除小吃分类 40 道，也排除地方菜系内标为小吃的 5 道。
- 菜库从 104 道增至 168 道；八大菜系各 15 道、家常菜 8 道、小吃 40 道。
- 真实照片替换原菜品插画。所有图放在本地 assets/photos，显示作者、许可、来源；同类参考说明实际图像内容。
- 冰箱食材匹配，列出已齐配方和缺少的配料，提供默认常用调料开关。

## 本轮修复

- 同一随机菜单跨洗牌周期仍保持唯一，不能重复凑够用户请求数量。
- 明确的食材别名能匹配实际菜谱：红薯/细长红薯、鲜虾/虾、猪五花肉/五花肉等。
- 青红甜椒按两项必需食材计算；只输入一种时显示另一种缺料。
- 生米不能代替熟米饭，不同肉种、花生酱与芝麻酱不能误匹配。
- 蒸鱼豉油与专用淀粉不自动当成常用调料，避免错误显示主料已齐。
- 多标签页按字段保存数据，收藏和抽签不会覆盖另一页保存的冰箱食材。
- 搜索防抖尚未结束时打开收藏、历史或说明弹窗，会先应用待处理搜索。
- 查看菜单、收藏和冰箱中的菜谱后，键盘焦点移到菜名；看做法时移到制作步骤。
- 手机输入框增大字号，图片失败时仍保留文字菜谱和重抽功能。

## 验证方式

`npm run build` 生成实际交付的 HTML；`npm test` 检查菜库、筛选、随机、冰箱逻辑和完整照片资产。

`node scripts/browser-check.cjs` 使用本机 Chrome 与 Playwright 检查完整交互。视口为 320×740、390×844、768×1024、1440×1050；检查多菜菜单和冰箱结果不溢出、手机抽签按钮可见。包含跨标签页、损坏/禁用存储、搜索竞态、离线 file 打开、照片加载和无运行时错误检查。

图片与菜谱以家常参考为定位，没有逐道实际试做。手机验证为浏览器视口与交互检查，未操作实体手机。

## 本地最终结果

- `npm run build`：168 道菜谱、168 个照片映射，生成约 367.9 KiB 的 HTML。
- `npm test`：24 / 24 通过，包括照片覆盖、文件格式、逐图许可信息与内嵌清单一致性。
- Chrome 浏览器检查：14 组通过，覆盖四种屏幕尺寸，未发现运行时错误。
- 145 张独立 WebP 均能完整解码，共 13,409,968 字节。78 道菜名匹配，90 道明确标注同类、主材或做法参考。
